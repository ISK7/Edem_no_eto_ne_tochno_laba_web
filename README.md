# «Едем, но это не точно»

Информационная система записи на тест-драйв: клиент выбирает автомобиль, дату,
время и способ оплаты, оставляет заявку, а администратор подтверждает, завершает
или отклоняет её с обязательной причиной.

Учебный проект по дисциплине «Веб-программирование». Реализованы все три модуля
задания; итоговый объём соответствует модулю 3.

## Стек

- **Frontend:** React 19, TypeScript, React Router 7, Vite 6
- **Backend:** Node.js, Express 4, TypeScript
- **База данных:** SQLite + Prisma ORM 6
- **Аутентификация:** JWT (access + refresh), PBKDF2-HMAC-SHA256, httpOnly-cookie
- **Стили:** собственный CSS с дизайн-токенами, адаптивность от 390 px

## Быстрый старт

Требуется Node.js **20.12+** (проверено на Node 22).

```bash
npm install
npm run db:setup
npm run dev
```

После запуска:

- сайт — <http://localhost:5173>
- API — <http://localhost:4000/api>
- проверка сервера — <http://localhost:4000/api/health>

Команда `db:setup` создаёт клиент Prisma, применяет схему к SQLite и заполняет
базу демонстрационными данными. Файл базы: `back/prisma/dev.db`.

### Переменные окружения

Файл `.env` уже создан для локального запуска. Шаблон находится в
`.env.example`:

```env
PORT=4000
NODE_ENV=development
ACCESS_TOKEN_SECRET=replace-with-random-32-chars
REFRESH_TOKEN_SECRET=replace-with-another-random-32-chars
ACCESS_TOKEN_TTL=900
REFRESH_TOKEN_TTL=604800
```

В production секреты обязательны: сервер не стартует без
`ACCESS_TOKEN_SECRET` и `REFRESH_TOKEN_SECRET`.

### Production-сборка

```bash
npm run build
npm start
```

Сайт и API будут доступны на <http://localhost:4000>. Express раздаёт
`front/dist` и перенаправляет все не-API маршруты на `index.html`, поэтому
прямые ссылки вида `/admin` работают и после сборки.

## Демонстрационные аккаунты

| Роль          | Логин      | Пароль    |
|      ---      |    ----    |    ----   |
| Администратор | `avto2024` | `poehali` |
| Пользователь  | `демо01`   | `demo123` |

Администратор создаётся как обычный пользователь с ролью `ADMIN`. Демо-пользователь
имеет 8 заявок во всех статусах. Данные администратора не выводятся на странице
входа.

## Возможности

### Клиент

- регистрация с уникальным логином от 3 до 32 символов: латиница или кириллица, цифры, `_` и `-`;
- вход, выход, восстановление сессии после перезагрузки;
- история заявок и счётчики по статусам;
- фильтр заявок по статусу и сортировка по дате или марке автомобиля;
- создание заявки: марка и модель, адрес, контактный телефон, серия и номер
  водительского удостоверения, дата выдачи, дата и время визита, способ оплаты;
- фиксированная стоимость услуги для каждой модели: показывается при выборе
  автомобиля, в блоке оплаты и в сводке заявки;
- количество автомобилей каждой модели в парке и общий размер парка на главной;
- живая сводка заявки;
- обязательное согласие с правилами: без него кнопка отправки заблокирована;
- подробности заявки и причина отклонения;
- сообщения об ошибках входа и валидации.

### Администратор

- все заявки с контактами и данными клиента;
- поиск по ФИО, логину, телефону, email, автомобилю и номеру заявки;
- фильтр по статусу, сортировка по дате создания, дате визита или марке автомобиля;
- пагинация по 6 записей;
- смена статуса: одобрено, выполнено, отклонено;
- обязательная причина отклонения (5–300 символов);
- расписание заявок на день справа от списка: календарь с отметками занятых дат,
  24-часовой шкалой, цветными полосами статусов, подписями моделей и меткой
  текущего времени;
- модальное окно с полными данными заявки;
- всплывающие уведомления о результате действий.

### Интерфейс

- адаптивная вёрстка, проверенная при 390×844;
- мобильная нижняя навигация;
- анимации появления, скелетоны загрузки, состояния кнопок;
- поддержка `prefers-reduced-motion`;
- семантическая разметка, подписи полей, `aria-invalid` и фокус на первой ошибке.

## API

Все ответы — JSON. Защищённые маршруты требуют `Authorization: Bearer <access>`.

| Метод   | Маршрут                          | Доступ       | Назначение                      |
|   ---   |               ---                |     ----     |              ----               |
| `GET`   | `/api/health`                    | все          | проверка БД                     |
| `POST`  | `/api/auth/register`             | все          | регистрация                     |
| `POST`  | `/api/auth/login`                | все          | вход                            |
| `POST`  | `/api/auth/refresh`              | cookie       | новая пара токенов              |
| `POST`  | `/api/auth/logout`               | cookie       | отзыв refresh-токена            |
| `GET`   | `/api/auth/me`                   | пользователь | текущий профиль                 |
| `GET`   | `/api/catalog/cars`              | все          | марки и модели                  |
| `GET`   | `/api/requests`                  | пользователь | свои заявки                     |
| `POST`  | `/api/requests`                  | пользователь | создать заявку                  |
| `GET`   | `/api/admin/requests`            | админ        | список с фильтрами и пагинацией |
| `GET`   | `/api/admin/schedule`            | админ        | все заявки для расписания       |
| `PATCH` | `/api/admin/requests/:id/status` | админ        | сменить статус                  |

Ошибки имеют единый формат:

```json
{
  "error": {
    "message": "Проверьте поля формы",
    "code": "VALIDATION_ERROR",
    "fields": { "login": "Введите логин" }
  }
}
```

## Безопасность

- пароли хранятся как PBKDF2-HMAC-SHA256-хеши с солью (20 000 итераций; выбрано
  ради скорости работы входа, поэтому запас ниже рекомендованного для
  production-систем); старые scrypt-хеши продолжают проверяться;
- access-токен живёт 15 минут и хранится только в памяти frontend-модуля;
- refresh-токен живёт 7 дней, передаётся в `httpOnly`, `SameSite=Lax` cookie;
- в базе хранится не сам refresh-токен, а его хеш и `jti`;
- refresh-токены ротируются при обновлении, старые отзываются;
- вход и регистрация ограничены rate limit;
- сервер проверяет роли и валидирует все входные данные независимо от клиента;
- установлены базовые security-заголовки (`nosniff`, `DENY`, `no-referrer`,
  `Permissions-Policy`);
- секреты JWT не попадают в клиентский код.

## Схема базы данных

ER-диаграмма: [`docs/database-diagram.html`](docs/database-diagram.html)
([SVG](docs/database-diagram.svg)).

Тест-драйв — платная услуга с фиксированной стоимостью для каждой модели. Она не
связана с покупкой автомобиля и не создаёт обязательств по его приобретению.

Таблицы:

- `User` — пользователи и администраторы;
- `RefreshToken` — активные сессии;
- `CarBrand` — марки автомобилей;
- `CarModel` — модели, уникальные внутри марки, с фиксированной ценой услуги
  и количеством экземпляров в парке (`quantity`);
- `TestDriveRequest` — заявки на тест-драйв.

SQLite не поддерживает `enum`, поэтому `role`, `status` и `paymentType` хранятся
строками и проверяются приложением. Для поиска по кириллице без учёта регистра в
заявке хранится предвычисленное поле `searchIndex` в нижнем регистре.

## Решение проблем с базой

### `npm run db:setup` не выполняется

1. Остановите запущенный `npm run dev` — SQLite может блокировать файл.
2. Убедитесь, что существует каталог `back/prisma`.
3. Проверьте `back/prisma/.env`: `DATABASE_URL="file:./dev.db"`.
4. Повторите `npm run db:setup`.

### Ошибка «Prisma Client not initialized»

Выполните:

```bash
npm run db:generate
```

### Порт занят

Измените `PORT` в `.env` для API. Для Vite порт задан в
`front/vite.config.ts` (5173, `strictPort: true`); при необходимости измените его
и прокси `/api` на новый порт API.

### В консоли вместо кириллицы «кракозябры»

Это особенность кодировки консоли Windows. JSON-ответы и сайт используют UTF-8;
на работу приложения это не влияет. Для корректного вывода можно выполнить
`chcp 65001` в PowerShell.

### Полный сброс демо-базы

Остановите сервер, удалите `back/prisma/dev.db` и выполните:

```bash
npm run db:setup
```
